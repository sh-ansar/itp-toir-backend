# Архитектурный и технический аудит — ITP ТОиР

Проверено 04.11.2026, feature/toir-foundation. Это снимок состояния, а не обещание отсутствия дефектов.

## Вывод

**Бизнес-ядро работоспособно, но до зрелой передачи/промышленного расширения есть инженерный долг.** Прежде всего нужны эксплуатационные стандарты, статический анализ frontend, декомпозиция тяжёлых компонентов и отдельное подтверждение нагрузочной устойчивости SQLite.

### Что подтверждено

- Laravel 12, PHP 8.4 server, Vue 3 + TypeScript + Pinia + Vite, независимые репозитории и production-процессы.
- Backend: 89 feature/unit тестов, 827 assertions (на дату аудита), SQLite :memory:, GitHub Actions success.
- Laravel Pint: **111 PHP файлов успешно проверены** после отдельного форматирования; PHP code style теперь проверяется CI.
- Frontend: vue-tsc и Vite production build проходят.
- На изолированном QA-контуре: 9 тестовых аккаунтов, 2 компании; 23 реальных API-сценария, 53 браузерные проверки, 23 страницы и 18 адаптивных проходов; SQLite восстановлена и отдельный экземпляр повторно авторизовал пользователя.
- Production и другие системы не затрагивались QA-базой; production-сайт доступен. Проверка SMTP-доставки всё ещё не закрыта.
- Секреты .env и production SQLite не входят в Git-дерево.

## Отмеченные риски и приоритеты

| Уровень | Проблема | Рекомендуемая работа |
|---|---|---|
| P0 / эксплуатация | Нет подтверждения реальной SMTP-доставки в production | Настроить/проверить transport по отдельной change-процедуре и отправить контрольное письмо |
| P0 / масштабирование | SQLite production, конкурирующие записи на склад/наряды и много компаний не проходили нагрузочный прогон | Межсессионные и многопроцессные тесты, план перехода на PostgreSQL до массового onboarding |
| P0 / операционная зрелость | Нужно формально оформить мониторинг, регламент периодических бэкапов и проверку восстановления production | Закрепить RPO/RTO, расписание и владельца процесса |
| P1 / backend | Повторяющиеся проверки компании/роли в контроллерах, большой ToirResourceController (~542 строк) и ToirPlanningService (~516 строк) | CompanyContext + Policies/FormRequest, выделение сервисов по домену, малыми PR под тесты |
| P1 / frontend | DetailView (~580), ChatView (~463), toir-modules.css (~841), нет отдельного ESLint/Prettier-gate | Делить по состояниям/вкладкам, вводить UI-lint поэтапно |
| P1 / frontend | После удаления демо осталось 87 ссылок preview.enabled (store всегда false) | Отдельный механический refactor с TypeScript/Playwright тестами |
| P1 / UI parity | 22 нативных select в шаблонах вместо полностью единого набора компонентов | Поэтапно заменить на общий Select/MultiSelect с keyboard/a11y |
| P1 / API | Нет OpenAPI схемы и генерации клиентов, часть схемы в контроллерах | Стабилизировать DTO/ответы и документацию контрактов |
| P1 / локализация | RU/EN/GE не гарантированы для всех новых сообщений/страниц | Автопроверка отсутствующих ключей переводов и смешанных строк |
| P1 / нагрузка | Reverb/chat outbox: реальные нагрузочные/отказоустойчивые тесты не подтверждены | Тесты переподключения, повторов, concurrency и фоновых сбоев |
| P2 / юридическое | В composer.json указан license MIT (возможно перенесён из Laravel skeleton) | Владелец продукта/юрист должен подтвердить требуемую лицензию для корпоративного кода |
| P2 / совместимость | Заявлена версия PHP ^8.2 и возможность иных БД, но приёмка фактически на PHP 8.4/SQLite | Матрица CI для нужных платформ либо сузить заявленную поддержку |

## Что НЕ найдено при текущем аудите

- Отслеживаемых production .env, .sqlite и приватных ключей в проверенных Git-деревьях.
- Прямой зависимости backend ТОиР от БД HRM/Portal/Inventory.
- Массовых ошибок Laravel тестов и ошибок TypeScript/Vite в существующей feature-ветке.

Это не заменяет SAST, зависимостной проверки supply-chain, pentest и нагрузочных испытаний. Все не охваченные сценарии считаются непроверенными, а не автоматически безопасными.

## Стандарты для сопровождения

- backend: Laravel Pint, PHP 8.4 CI, Laravel feature-тесты и изолированные миграции;
- frontend: TypeScript typecheck, production build; добавить в будущем ESLint и тесты компонентов;
- единая компания из сессии, серверная проверка role и FK; транзакции и аудит в каждой критичной операции;
- UI: Golos Text, семантические CSS-переменные, общие компоненты, одинаковые состояния ошибок и адаптация;
- Git: отдельные коммиты форматирования, функциональности, миграций и документации; PR + CI перед релизом;
- production: скрипты и секреты только на сервере, проверенные бэкапы и откат.

**Рекомендация:** можно передать другому разработчику для продолжения разработки уже сейчас вместе с этим пакетом документов. Но нельзя утверждать, что система готова к высоконагруженному многокорпоративному production без завершения P0-операционных и нагрузочных проверок.
