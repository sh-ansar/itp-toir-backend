# ITP ТОиР — перенос публичного сайта и коммерческого контура

Область: **только** `/mro/` и выделенное приложение `itp-toir-backend`. Portal, HRM и Inventory не затрагивать.

## Состав
- Публичный лендинг Portal с брендом ITP ТОиР, разделы возможностей и отраслей, интерактивная демонстрация с синтетическими данными.
- Публичный каталог тарифов; конструктор версий и публикации; назначение подписки компании.
- Изолированная супер-админка: компании, пользователи, тарифы, счета, юридические версии, согласия, права.
- Счета/PDF, реквизиты покупателя и поставщика, подтверждения оплат; финансовые операции отключены по умолчанию.
- Регистрация: только после подтверждения email; сильный пароль; IP throttle.
- RU/EN/GE/DE/FR/ES на публичных экранах и в коммерческих компонентах; в основном приложении остаётся существующий набор языков.

## Маршруты
| URL (через Apache) | Назначение |
|---|---|
| `/mro/` | публичный лендинг |
| `/mro/pricing` | тарифы |
| `/mro/register`, `/mro/register/verify` | регистрация и подтверждение |
| `/mro/legal/*` | опубликованные юридические документы |
| `/mro/login` | существующая авторизация |
| `/mro/dashboard` | рабочий стол оборудования |
| `/mro/admin/*` | супер-админка с отдельными правами |
| `/mro/billing` | счета и подписка компании |
| `/mro/api/v1/*` | MRO API, проксируется в `/api/v1/*` (ТОиР backend) |

## Архитектурная изоляция
Таблицы коммерческого контура имеют префикс `mro_*`. Права выдаются только в `mro_admin_grants`. Пользователи должны быть подтверждены, активны и иметь активное членство в компании ТОиР. Никаких запросов к базе Portal и общих супер-администраторских прав нет.

## Условия перед боевой публикацией
1. Подтвердить неизменность релиза других приложений и создать резервную копию `C:/deploy/toir/backend/current/database/database.sqlite`, файлов backend, сайта и текущей `.env`.
2. Проверить отличие ветки от текущей файловой версии ТОиР. **Не копировать целиком** исходную ветку поверх сервера: `ToirStockController.php` и `routes/web.php` уже имеют независимые изменения. Переносить коммерческие файлы отдельно, а в web.php добавить только `require __DIR__.'/mro_commercial.php';`.
3. Установить PHP-зависимости из `composer.lock` с проверкой PHP 8.2, intl, gd. Не перезаписывать `.env`, `storage/`, SQLite, пользователей или сессии.
4. Установить SMTP **только в конфигурации ТОиР**; использовать источник HRM лишь после проверки доступа/полномочий, не копировать `APP_KEY` или DB-конфигурацию. Текущий `MAIL_MAILER=log` не подходит для публичной регистрации. Отдельно проверить реальную доставку тестового письма.
5. Адаптировать тексты юридических документов к ТОиР и пройти юридическое согласование. Публиковать версии только после проверки реквизитов оператора/страны/обработки данных. Не представлять черновики как действующие условия.
6. Создать 3 актуальных тарифных плана через супер-админку, согласовать реальные цены и лимиты и опубликовать. Никаких выдуманных цен и автоматического списания.
7. По результатам одобрения включить `MRO_LEGAL_PUBLICATION_ENABLED`, `MRO_BILLING_ENABLED`, `MRO_INVOICE_ISSUANCE_ENABLED` в требуемой последовательности. `MRO_SUBSCRIPTION_ENFORCEMENT_ENABLED` оставить false до проверки пилотных клиентов.
8. Собрать фронтенд с `VITE_BASE_PATH=/mro/`; публиковать только в `C:/deploy/toir/site/current` после резервной копии, не в `C:/xampp/htdocs/platform`.
9. Проверить end-to-end: /mro, документы и тарифы, email-верификацию, логин, кабинет компании, матрицу прав, создание/просмотр PDF, обратный путь /mro/dashboard, смартфон 320 px.
10. Только после всех проверок объявлять релиз завершённым.

## Bootstrap супер-администратора
Команда `php artisan mro:grant-admin <email>` принимает **только** существующую подтверждённую активную учетную запись с доступом к компании ТОиР. Запись создаётся в `mro_admin_grants`. Не назначайте права пользователям Portal автоматически.

## Параметры
- `TOIR_FRONTEND_URL=https://platform.itpmining.kz/mro`
- `MRO_PUBLIC_REGISTRATION_ENABLED=false (только после публикации оферты и privacy)
- MRO_SUBSCRIPTIONS_ENABLED=true`
- `MRO_SUBSCRIPTION_ENFORCEMENT_ENABLED=false`
- `MRO_BILLING_ENABLED=false`
- `MRO_PAYMENT_COLLECTION_ENABLED=false`
- `MRO_INVOICE_ISSUANCE_ENABLED=false`
- `MRO_LEGAL_PUBLICATION_ENABLED=false`

## Откат
Остановить только изолированные процессы ТОиР; восстановить зарезервированные файлы и БД ТОиР в согласованной точке, не затрагивая Portal/HRM/Inventory. Миграции не откатывать без предварительного анализа появившихся данных. Проверить /mro/api/v1/health, /mro/login и /mro/dashboard после возврата.
